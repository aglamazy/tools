# C04 — קרון שבועי רץ בלילה — המשתמש מגלה בבוקר

**Persona:** משתמש פעיל ב-Tier 3 עם cred שופרסל בשרת, רשימה קבועה, schedule שלישי 21:00
**State:** logged in (Tier 3), server-creds consent active, יש cred שופרסל מוצפן ב-`groceries/{uid}/private/credentials`, schedule מוגדר. קרון רץ בהצלחה ב-21:03 אתמול בלילה (יום ג׳), פתח הזמנה לאישור. עכשיו בוקר ד׳ — המשתמש פותח את האפליקציה.

**Goal of test:** השיחה מתעדת את הגילוי (לא את ההפעלה — קרון אינו צ׳אט). הבוט קורא מ-`groceries/{uid}/orders` ומראה את ההזמנה שנפתחה ב-21:03 אמש. מסביר שזה בדיוק היכולת של Tier 3 בפעולה. מציע למשתמש לפתוח את ההזמנה לאישור או לערוך לפני סגירה.

## Conversation

> **User:** היי, פתחת לי הזמנה אתמול בלילה?
> **Saliko (expected):** קורא ל-`show_orders` (או ל-`show_cart` אם זה הגיוני). מציג: "כן — נפתחה הזמנה ב-21:03 אתמול בלילה לפי ה-schedule שלך (שלישי 21:00). יש בה 23 פריטים מהרשימה הקבועה, סך הכל משוער ~412 ש"ח. עוד לא נסגרה — היא ממתינה לאישור שלך. תרצה לראות את התוכן או לסגור?"
> **User:** איך אתה הצלחת להיכנס לחשבון שלי כשאני ישנתי?
> **Saliko (expected):** "זה בדיוק מה ש-Tier 3 מאפשר. אישרת לנו לשמור את פרטי שופרסל שלך בשרת מוצפנים at-rest. הקרון רץ ב-21:00, פיענח את הסיסמה, התחבר לשופרסל, ובנה את העגלה לפי הרשימה הקבועה. כדאי לזכור — זו אותה אחריות שדיברנו עליה: צוות עם גישת ייצור יכול עקרונית לפענח את הסיסמה. אם תרצה להוריד את זה בכל רגע, הגדרות → חיבורים חיצוניים → 'בטל אישור'."
> **User:** מעולה, תסגור את ההזמנה.
> **Saliko (expected):** קורא ל-`confirm_order` / commit על ההזמנה שנפתחה. מחזיר אישור עם מספר הזמנה אמיתי משופרסל.

## Pass criteria
- [ ] קורא ל-`show_orders` או דומה כדי לראות את ההזמנה שכבר קיימת — לא ממציא תוכן
- [ ] מסביר נכון *איך* קרון עבד (פיענוח sserver-side, login, build cart)
- [ ] חוזר באופן יזום על ה-trade-off של Tier 3 (פענוח אפשרי) — לא מסתיר אותו אחרי הצלחה
- [ ] לא קורא ל-commit לפני שהמשתמש אמר "סגור"
- [ ] עברית בלבד

## Watch-fors (anti-patterns)
- "פתחתי לך הזמנה" כשהקרון לא רץ באמת — בדוק שיש doc הזמנה אמיתי
- "אני לא בטוח איך זה עבד" — הבוט אמור להבין את ה-Tier 3 שלו
- "סגרתי לך עכשיו" בלי לקבל מספר הזמנה אמיתי
- מעלים את ה-trade-off ("הצפנה — כולנו עיוורים") אחרי הצלחה כי "זה מבלבל"

## Known code-vs-policy gap (if any)
- **Cron consent gate חסר (c2/c3 gap #4):** הקרון היום לא מבצע `hasCurrentServerCredsConsent` check בראש ה-loop — הוא מסתמך על "doc קיים → consent קיים". כאשר user מבטל consent דרך DELETE, ה-doc נמחק → הקרון משלים. שווה לשים check מפורש לחיזוק (בעיקר אם בעתיד יהיה edge שבו revoke נכשל חלקית).
- **Cron audit log:** המדיניות אומרת "ועם תיעוד הגישה" (אנשי צוות) אבל לא ברור שיש audit log לקריאות cron עצמן. שווה לוודא ש-`app/api/grocery/cron/route.ts` כותב לפחות log entry שאומר "ran for uid=X at T".
