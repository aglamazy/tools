# B01 — הרשמה ראשונה + חיבור חנות דרך הגדרות (Dexie-only)

**Persona:** משתמש חדש שזה עתה נרשם דרך Google sign-in; מבין באבטחה ומעדיף ברירת מחדל שמרנית
**State:** logged in (Tier 2), no server-creds consent, אין creds בכלל (לא ב-Dexie ולא בשרת), **T&C מודאל עדיין פתוח** — המשתמש עוד לא לחץ "אני מאשר"
**Goal of test:** (1) זרימת T&C accept מובילה את המשתמש פנימה. (2) הבוט מסביר נכון שברירת המחדל היא Tier 2, מפנה לחיבור דרך ההגדרות (לא דרך הצ׳אט), ולא מציע opt-in ל-Tier 3 ביוזמתו.

## UI interaction — אישור T&C לפני הצ׳אט

לפני שהצ׳אט נפתח, המודאל של תנאי השימוש (T&C) נמצא על המסך וחוסם אינטראקציה. בדיקה:

1. צלם snapshot של המסך.
2. ודא שמופיע מודאל T&C עם כפתור "אני מאשר" (או דומה — אישור / להתחיל / accept). אם אין מודאל כזה, ייתכן שהמשתמש כבר אישר בעבר — מבלי לפגוע, רק תרשום "T&C already accepted (no modal)" וקפוץ ל-section הצ׳אט.
3. לחץ על הכפתור "אני מאשר".
4. ודא שהמודאל נסגר ו-`users/{uid}.tcAcceptedAt` בFirestore עודכן (אופציונלי — אפשר לבדוק ב-DevTools → Application → IndexedDB או דרך הרשת tab).
5. ודא ש-Chat bubble זמין כעת ולא חסום.

**Pass criteria for the T&C accept step:**
- [ ] המודאל סגר אחרי הלחיצה
- [ ] לא נדרשה אינטראקציה נוספת לפני שהצ׳אט הופיע
- [ ] אין error toast / banner
- [ ] (אופציונלי) `tcAcceptedAt` עודכן בשרת

## Conversation

> **User:** היי, נרשמתי עכשיו. איך אני מחבר את החשבון של שופרסל?
> **Saliko (expected):** "ברוך הבא. ברירת המחדל אצלך היא Tier 2 — סיסמת שופרסל תישמר רק בדפדפן שלך (IndexedDB), עם גיבוי מוצפן end-to-end לסנכרון בין מכשירים. השרת שלנו לא רואה את הסיסמה. כדי לחבר תיגש להגדרות → חיבורים חיצוניים → הוסף פרטי גישה לשופרסל. שם זה נשמר מקומית בדפדפן."
> **User:** ולמה לא ישר פה בצ׳אט?
> **Saliko (expected):** "אפשר גם פה — אבל ברמת ברירת המחדל שלך (Tier 2) הפרטים יישמרו רק בדפדפן הזה, וההגדרות נותנות לך תצוגה ברורה של מה שמור איפה ואפשרות לערוך/למחוק. אם בכל זאת נוח לך בצ׳אט — תגיד לי את האימייל והסיסמה והם יכנסו לאותו vault מקומי."
> **User:** איך אני יודע שזה נשמר מקומי באמת ולא הולך לשרת?
> **Saliko (expected):** מציע לאמת — Open DevTools → Application → IndexedDB → financeDB → credentials. מציין במפורש שאין POST לשרת מהזרימה הזו כל עוד לא נתת אישור מפורש ל-Tier 3 (שלא ביקשת ולא מומלץ אם לא צריך cron).

## Pass criteria
- [ ] מציין במפורש Tier 2 כברירת המחדל
- [ ] מסביר שהסיסמה נשמרת ב-IndexedDB ולא בשרת
- [ ] לא דוחף ל-Tier 3 ביוזמתו (המשתמש לא ביקש cron)
- [ ] מציע מסלול דרך הגדרות → חיבורים חיצוניים
- [ ] עברית בלבד
- [ ] לא מבקש פרטי אשראי / כרטיס בכלל

## Watch-fors (anti-patterns)
- "אני אשמור לך בשרת מוצפן" בלי שהמשתמש ביקש Tier 3
- "הסיסמה לא נשמרת בכלל" — לא נכון; היא ב-Dexie
- מציע Tier 3 כברירת מחדל / "מומלץ"
- שולח את המשתמש לעמוד הגדרות שלא קיים (להגיד "חיבורים חיצוניים" — שם הטאב הנכון)
